# Обработка заявок на восстановление пароля (служба поддержки)

## Обзор

В проекте используется ручной сценарий восстановления пароля:

1. Пользователь на сайте открывает страницу «Восстановление пароля» и отправляет email.
2. Система создаёт заявку в базе данных.
3. Администратор обрабатывает заявку через Django Admin, генерирует одноразовую ссылку сброса и отправляет её пользователю вручную.

Письма системой не отправляются автоматически.

---

## Где смотреть заявки

1. Откройте админку: `/sm-admin/`
2. Раздел: **Accounts → Заявки на сброс пароля**

В списке отображаются:
- email
- привязанный пользователь (если найден по email)
- статус
- дата создания
- кто и когда начал обработку

---

## Как обработать заявку

### 1) Найдите заявку

- Откройте список заявок
- При необходимости используйте поиск по `email` или по `user.email`

### 2) Проверьте привязку пользователя

В заявке поле `user` может быть пустым, если:
- email введён с ошибкой
- у пользователя нет email в профиле
- пользователя в системе нет

Если `user` пустой:
- найдите пользователя в админке (Users)
- проверьте корректный email
- при необходимости свяжитесь с пользователем для уточнения

### 3) Сгенерируйте одноразовую ссылку

- В списке заявок отметьте **ровно одну** заявку
- В выпадающем меню действий выберите:
  - **Сгенерировать одноразовую ссылку для сброса пароля**
- Нажмите **Выполнить**

Результат:
- админка покажет сгенерированную ссылку (в сообщении сверху)
- заявка будет переведена в статус **В работе**
- поля `processed_at` и `processed_by` заполнятся

Формат ссылки:

`{FRONTEND_URL}/reset-password/confirm?uid=...&token=...`

### 4) Отправьте ссылку пользователю

Администратор отправляет ссылку пользователю вручную (email/мессенджер).

Рекомендуемый текст:

- «Вы запросили восстановление пароля. Перейдите по ссылке и задайте новый пароль: <ссылка>. Ссылка одноразовая/временная.»

### 5) Закройте заявку

После того, как пользователь подтвердил, что пароль изменён:
- откройте заявку
- установите статус **Закрыта**
- (опционально) добавьте заметку в `note`

---

## Требования к настройкам

### FRONTEND_URL

Чтобы админка могла формировать полноценную ссылку, на сервере должна быть задана настройка `FRONTEND_URL`.

Если `FRONTEND_URL` не задан, админка вместо ссылки покажет только `uid` и `token`.

Рекомендуемое значение на проде:

- `FRONTEND_URL=https://beachplay.ru` (пример)

---

## Безопасность

- Ссылка содержит токен сброса пароля и должна передаваться пользователю только по доверенному каналу.
- Запросы на сброс пароля не раскрывают, существует ли email в системе.
- Сгенерированный токен валиден ограниченное время и перестаёт работать после смены пароля.
